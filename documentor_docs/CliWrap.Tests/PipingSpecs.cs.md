# Documentation: `CliWrap.Tests/PipingSpecs.cs`

## Overview

The `CliWrap.Tests/PipingSpecs.cs` file contains a comprehensive xUnit test suite for validating the stream piping functionality of the **CliWrap** library. The test specifications cover piping data into Standard Input (`stdin`), piping Standard Output (`stdout`) and Standard Error (`stderr`) into various targets, combining or merging pipe targets, command chaining, exception handling, and deadlock/hang prevention under various edge cases.

All test methods in this class use xUnit's `[Fact]` attribute with a 15-second timeout (`Timeout = 15000`) and leverage **FluentAssertions** for verifying test outcomes.

### 1. Standard Input (`stdin`) Piping

These tests verify that input data can be piped into a process's `stdin` from multiple data sources, using both explicit `PipeSource` factory methods and piped operator overloads (`|`).

| Test Method | Source Type Tested | Description |
| :--- | :--- | :--- |

| `I_can_execute_a_command_and_pipe_the_stdin_from_a_sync_anonymous_source` | Sync Anonymous Delegate | Pipes data using `PipeSource.Create` with a synchronous writer callback. |
| `I_can_execute_a_command_and_pipe_the_stdin_from_a_stream` | `Stream` (`MemoryStream`) | Pipes standard input directly from a `Stream` object using the `\|` operator. |
| `I_can_execute_a_command_and_pipe_the_stdin_from_a_file` | File Path | Pipes input from a temporary file using `PipeSource.FromFile(...)`. |
| `I_can_execute_a_command_and_pipe_the_stdin_from_memory` | `ReadOnlyMemory<byte>` | Pipes raw binary memory buffers using the `\|` operator. |
| `I_can_execute_a_command_and_pipe_the_stdin_from_a_byte_array` | `byte[]` | Pipes byte arrays directly into a command using the `\|` operator. |
| `I_can_execute_a_command_and_pipe_the_stdin_from_a_string` | `string` | Pipes text strings directly into a command using the `\|` operator. |
| `I_can_execute_a_command_and_pipe_the_stdin_from_another_command` | `Command` | Pipes stdout of one command into stdin of another command (`Command1 \| Command2`). |
| `I_can_execute_a_command_and_pipe_the_stdin_from_another_command_with_a_transform` | Transformed Command Source | Uses `PipeSource.FromCommand` with a custom async transformation step (reads 5000 bytes and discards the rest). |
| `I_can_execute_a_command_and_pipe_the_stdin_from_a_chain_of_commands` | Command Chain | Chains multiple commands together (`string \| Command1 \| Command2 \| Command3`). |

### 4. Target Merging & Hierarchical Targets

Tests how `PipeTarget.Merge` fan-outs command output to multiple targets simultaneously.

- **`I_can_execute_a_command_and_pipe_the_stdout_into_multiple_targets`**: Verifies that merging three stream targets writes identical binary output to all three target streams.
- **`I_can_execute_a_command_and_pipe_the_stdout_into_multiple_streams_with_a_large_buffer`**: Regression test ensuring large output buffers (`--buffer 100000`, length `1000000`) write complete and correct data across merged targets.
- **`I_can_execute_a_command_and_pipe_the_stdout_into_multiple_targets_and_not_hang_on_large_stdout_if_one_of_the_targets_throws_an_exception`**: Verifies that if one merged target throws an exception, execution fails fast and does not hang on large stdout streams.
- **`I_can_execute_a_command_and_pipe_the_stdout_into_multiple_targets_and_not_hang_if_one_of_them_reads_past_the_end_of_stream`**: Ensures that reading past EOF in one target stream returns `0` bytes without deadlocking other merged targets.
- **`I_can_execute_a_command_and_pipe_the_stdout_into_a_hierarchy_of_targets`**: Verifies nested `PipeTarget.Merge` calls (a target hierarchy of 4 streams) replicate data uniformly.

### 5. Combined Execution (Buffered Execution + Piping)

Validates that `ExecuteBufferedAsync()` can be invoked on commands that simultaneously use pipe targets.

- **`I_can_execute_a_command_with_buffering_and_also_pipe_the_stdout_into_a_stream`**: Asserts that `ExecuteBufferedAsync()` correctly captures `StandardOutput` while simultaneously piping standard output into a `MemoryStream`.
- **`I_can_execute_a_command_with_buffering_and_also_pipe_the_stdout_into_a_sync_delegate`**: Asserts that `ExecuteBufferedAsync()` captures standard output and simultaneously invokes a synchronous delegate target line-by-line.

---

### 6. Exception Handling & Fault Tolerance

Ensures exceptions originating in sources or targets propagate cleanly and clean up running processes.

- **`I_can_try_to_execute_a_command_and_get_an_error_if_the_pipe_source_throws_an_exception`**: Validates exception throwing when the pipe source fails (e.g., trying to stream a non-existent file).
- **`I_can_try_to_execute_a_command_and_get_an_error_if_the_pipe_target_throws_an_exception`**: Validates exception throwing when the pipe target fails (e.g., writing to an invalid path).
- **`I_can_try_to_execute_a_command_and_not_hang_on_large_stdout_if_the_pipe_target_throws_an_exception`**: Ensures large stdout streams do not cause deadlocks if a pipe target delegate throws an exception.
- **`I_can_try_to_execute_a_command_and_have_it_finish_early_if_the_pipe_target_throws_an_exception`**: Confirms that when a target throws an exception, the underlying process is aborted and `Process.IsRunning(task.ProcessId)` resolves to `false`.

---

### 7. Deadlock & Edge Case Resilience

Tests specific edge cases related to process execution, input streams, and deadlock prevention.

- **`I_can_execute_a_command_and_not_hang_if_the_process_expects_stdin_but_none_is_provided`**: Ensures execution completes cleanly if a process expects stdin but no stdin source is piped.
- **`I_can_execute_a_command_and_not_hang_if_the_process_expects_stdin_but_empty_data_is_provided`**: Ensures an empty byte array (`Array.Empty<byte>()`) piped to stdin does not hang the process.
- **`I_can_execute_a_command_and_not_hang_if_the_process_only_partially_consumes_stdin`**: Tests continuous infinite-like stream writing where the target process terminates early after consuming a subset of data (100,000 bytes).
- **`I_can_execute_a_command_and_not_hang_if_the_process_does_not_consume_stdin`**: Verifies that if a process ignores stdin completely, execution finishes without hanging despite an active source delay.
- **`I_can_execute_a_command_and_not_hang_if_the_process_does_not_consume_stdin_even_if_the_source_cannot_be_canceled`**: Tests scenario where the source uses `CancellationToken.None` and the process ignores stdin.
- **`I_can_execute_a_command_and_not_hang_on_large_stdin_while_also_writing_stdout`**: Verifies concurrent non-blocking reading and writing when pumping large stdin payloads while simultaneously processing stdout output.
